## 1. 产品背景

### 1.1 项目背景

LangBot 作为一款生产级 IM 机器人平台，已支持飞书消息的发送和接收，但当前仅支持基础的文本消息和简单的卡片消息展示。**缺少用户交互能力**，导致无法满足复杂的业务场景需求。

### 1.2 用户痛点

| 痛点 | 描述 | 影响程度 |
|------|------|----------|
| **无法收集用户输入** | 用户只能发文字，无法填写表单 | ⭐⭐⭐⭐⭐ |
| **操作路径长** | 需要多次消息往返才能完成一个简单操作 | ⭐⭐⭐⭐ |
| **交互体验差** | 所有操作都在聊天窗口完成，缺乏引导 | ⭐⭐⭐ |
| **业务场景受限** | 无法做问卷调查、点餐、预约等场景 | ⭐⭐⭐⭐ |

### 1.3 目标用户

- **企业用户**：需要 AI 客服、工单处理、问卷调查
- **个人开发者**：需要构建交互式 AI 助手
- **运营人员**：需要活动报名、数据收集

### 3.2 核心功能列表

| 功能点 | 优先级 | 描述 |

|--------|--------|------|

| **用户识别** | P0 | 获取点击用户身份 |
| **多端同步** | P1 | 多用户操作状态同步 |

#### 功能模块 3：卡片生命周期管理

| 功能点 | 优先级 | 描述 |
|--------|--------|------|
| **卡片创建** | P0 | 创建交互式卡片消息 |

| **卡片撤回** | P1 | 自动/手动撤回卡片 |
| **超时处理** | P1 | 卡片超时自动清理 |

#### 功能模块 4：高级功能

| 功能点 | 优先级 | 描述 |
|--------|--------|------|
| **多轮对话** | P2 | 基于卡片的状态机对话 |
| **条件渲染** | P2 | 根据用户显示不同内容 |

## 4. 飞书卡片组件详细设计

### 4.1 组件清单

```
Card
├── header (可选)
│   ├── title
│   └── template (blue/green/red/grey/warning)
├── elements (必填)
│   ├── div (文本块)
│   ├── img (图片)
│   ├── action (按钮组)
│   │   └── button
│   │       ├── type: primary | default | danger
│   │       ├── url (链接按钮)
│   │       └── callback_id
│   ├── input (输入框)
│   │   ├── plain_text_input (单行)
│   │   └── paragraph_text_input (多行)
│   └── static_select (选择器)
│       └── option
├── actions (可选，按钮组)
└── config
    └── update_multi (是否支持多次更新)
```

### 4.2 回调数据结构

```json
// 飞书回调
{
  "action": {
    "callback_id": "btn_confirm",
    "value": {"order_id": "12345"},
    "tag": "button"
  },
  "operator": {
    "user_id": "ou_xxxxx"
  },
  "message": {
    "message_id": "om_xxxxx"
  }
}
```

```python
class FeishuCardPlatform:
    """飞书卡片平台能力"""

        self,
       接收方,

        回调查询
    ) -> CardMessageResult:
        """发送交互卡片"""
        pass
    
    async def update_card(
        self,
        消息ID,
        新卡片内容
    ) -> bool:
        """更新卡片"""
        pass
    
    async def handle_callback(
        self,
        回调数据
    ) -> CallbackResult:
        """处理回调"""
        pass
```

### 5.2 回调注册机制

```python
# 用户场景：注册回调处理器
@card.on_callback("confirm_order")
async def handle_confirm(callback_id, value, user_id):
    order_id = value.get("order_id")
    # 处理业务逻辑
    return {"type": "text", "content": f"已确认订单 {order_id}"}
```

## 8. 技术实现要点

### 8.1 回调消息配置

在飞书开放平台需要配置：
- `im.card.action.callback` 事件权限
- Webhook URL 配置

### 8.2 安全考虑

| 风险点 | 应对措施 |
|--------|----------|
| 回调伪造 | 验证签名 |
| 重复提交 | 幂等性设计 |
| 超时占用 | 状态超时清理 |
| 敏感数据 | 敏感信息脱敏 |
